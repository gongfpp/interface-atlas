# 私有浏览器验收

该隔离 QA 分支基于 `3a4a5e087d6a740cc63df3db18a66a50aad68ee2`。不修改 main、原任务分支或公开站点。

## 执行与证据

- `node scripts/verify-private-qa.mjs` 验证工作流保护和全部测试文件的请求隔离入口。
- 常规门禁：unit、Astro check、lint、完整 build、search:test。
- `npx playwright test --config=playwright.private-qa.config.mjs` 执行 Chromium 测试。
- 完整门禁前，先执行 21 项 Tooltip 视口边缘、重测、基础示例与离屏恢复检查；结果独立保存。
- 随后一个按钮计时场景与全部 16 个 Tooltip 桌面交错事件场景各独立重复五次，共 85 次；重试仍为零。测试仅修正时钟和指针位置假设，保留原有行为断言，并在 2.5 秒上限内观察原生滚动/实际几何停止，再确认移入提示前内容完全处于视口中。重复回归结果单独保存，不混入全量计数。
- 46 个组件的八套样式均覆盖中文 / 英文 × 390 / 1280 像素，共 1,472 次样式选择检查。
- 按钮、输入框、卡片、提示的每套样式均保存四种语言/宽度组合的成功截图，共计划 128 张；截图文件名标识组件、风格、语言和宽度。Tooltip 保留实际可视屏幕，避免把浮层裁切在控件容器内。
- 按钮、输入框和卡片的行为回归同样扩展至四种组合；提示保留鼠标、键盘和触屏模拟检查。
- 窄屏页头另测收藏、撤销及存储失败提示；布局几何报告区分页面溢出与合法的内部滚动容器。
- 报告中“收集到测试”不代表实际执行；截图已产生也不代表完成视觉人工审阅。

Actions artifact 名称包含运行提交 SHA。`commit.txt`、`tree.txt`、`parents.txt`、浏览器报告与截图哈希记录同一次运行的来源。报告、截图和失败 trace 只保存在当前私有仓库的七天期 artifact 中，不进入公开构建仓库。

## 发布保护

仅精确 QA 分支的 push 运行本工作流，job 再次核验私有仓库与分支。令牌仅有 contents: read，checkout 不持久化凭据。两个部署工作流的全部 job 显式关闭。本分支的隔离工作流不可直接合并到生产。

构建关闭分析和日志上报；测试 fixture 阻断非本地浏览器请求。失败注入使用 route.fallback 保留 allowlist，APIRequestContext 检查只允许本地目标并禁用重定向。不测试留言提交或登录。

本验收不包含真实 iOS/Android 硬件、WebKit/Firefox、第三方留言服务、公开部署或发布后验证。

玻璃按钮的文字使用不透明深色，针对配置中的全部渐变色标保留至少 4.5:1 的静态配色回归，并在双语、两种宽度的浏览器检查中核验实际前景色。此项修复不改变玻璃材质、布局或演示计时；它不是全站 WCAG 合规声明。判定依据：[W3C Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

原先把 Tooltip 失败仅归因于测试的滚动/指针竞态是不完整的。后续有界原生几何检查确认了实际边缘定位缺陷：触发器位于 1000px 视口的 y955.5 时，提示内容完全落在视口外。该问题需要产品定位修复；测试保留正常滚动路径，并继续验证视口边缘、重测与交互。

Tooltip 定位保留 DOM 归属，优先使用原生 manual-popover 顶层，翻转与限制视口边界，并在滚动、resize 和尺寸变化时重测。绝对定位回退的几何已做单元回归；它不能提供原生顶层的跨祖先裁剪/层叠保证，未据此声称旧浏览器已通过等价验收。

真实截图审阅还发现：瑞士风格原本透明的行项目作为独立浮层时，会透出下面的标题、分隔线和说明文字。仅该 Tooltip 的表面补为白色，保留黑色网格线和字重；共享样式配方及其他组件不变。单元测试与四种语言/宽度的浏览器计算样式检查防止回退，仍需复核实际截图。

## Firefox / WebKit 补充验收

保留 `e4f36d8beea1f6b71503ca3ef56fa068658b4012` 的 Chromium 已验收结果，在同一受保护私有分支增加独立引擎 job。使用锁定 Playwright 版本的官方 Firefox、WebKit 构建及系统依赖；各自先执行 16 个代表组合（128 张截图）和 135 个提示、按钮、输入框、卡片、页头及布局案例，两个阶段均通过后才执行全部 422 个案例。诊断阶段最多累计八个失败就停止当前命令，报告保留未执行数量，不将其视为完整通过；重试仍为零。

每个引擎独立保留源码 commit/tree/parent、运行时浏览器版本、JSON 结果、截图与哈希，artifact 仍为私有七天期。Chromium 的完整门禁同时保留，用于检查补充工作没有回退既有结果。

这是 [Playwright 官方浏览器构建](https://playwright.dev/docs/browsers)在 Linux CI 上的验收。WebKit 与 Apple Safari 产品、macOS/iOS 真机并不等价；最终通过范围以实际运行报告与截图审阅为准。

跨引擎首次运行中，WebKit 的两种语言 390px Tooltip 检查暴露了初次离屏挂载的独立问题：暂停的浮层仍为无边界的 `max-content` 隐藏盒，可能扩大文档宽度。暂停时移除该布局盒，锚点回到视口后再恢复原始 display 并测量。回归保留原生聚焦矩阵，并额外记录初次离屏聚焦前、立即之后和稳定后的宽度与浮层状态；不通过页面级裁切隐藏溢出。

## 临时预加载恢复 A/B 诊断

`50a3f868` 的 Chromium 与 Firefox 全量均通过；WebKit 全量为 416 通过、6 失败。五项是原生滚动期间点击移动风格按钮的测试前提问题，现复用有界几何观察，仍执行一次真实点击、原有选中断言及聚焦后的立即宽度断言。另一项与 [WebKit 270357](https://bugs.webkit.org/show_bug.cgi?id=270357) 的失败 modulepreload 缓存问题吻合：普通 reload 后不重新请求失败模块，不能用 503 替换原 abort 注入掩盖。

当前临时流水线仅执行私有 WebKit A/B，不重复完整验收：默认构建与显式 `astro.preload-qa.config.mjs` 候选各跑六项回归和十八项冷加载采样，报告分开保存。基线失败仍使 job 失败，没有重试、跳过或 `continue-on-error`。完成诊断后必须恢复完整门禁；不能把本次 A/B 当作完整通过。

默认 `astro.config.mjs` 未启用候选。候选使用 Vite client 环境配置，只取消 SolutionLab、ViewportPreview、DemoMount 三个源文件对应注册器的 JS 动态预加载；懒加载保留，其他路径沿用原策略。通过 bundler 的 `augmentChunkHash` 加入策略版本，避免手工改写已定名资产。构建对照拒绝同名 JS 内容变化，并核验仅三个注册器更名。

冷加载各采三次，记录三个注册器的请求、资源时间与界面就绪时间；另以每个本地 JS 请求额外 120ms 的人工延迟观察依赖串行成本。这是同一 CI 的诊断样本，不是实际公网或移动网络性能承诺。是否采用候选，须先核实恢复成功、请求变化及性能代价。
